# AI协作工作流协议 Lite v0.1

适用工具：Claude网页端 / Claude Code / CodeBuddy / Codex / zCode
存放位置：项目根目录 `docs/agent-workflow-protocol.md`
配套文件：项目根目录放 `CLAUDE.md`（Claude Code自动读取）/ `AGENTS.md`（其他支持此约定的工具自动读取），内容是指向本文件的一句话指引，不用每次手动提醒。

> Lite v0.1 相较此前版本的精简：砍掉了从未真正落地的验收报告文件引用；意图还原并入需求定稿，不再单独建文件；环境约束/需求池/决策日志三个项目级文件改为"按需创建"，不预先搭建空文件；设计探索加入前置判断，无实质技术不确定性时跳过分支/清算机制、走轻量设计通道；自检模板与清算模板只在本文件定义一次，各Skill文件引用而不复制。

## 一、核心原则

1. **草案优先，而非提问优先**——拿到需求先产出完整草案，用户改草案，不填问卷。
2. **大切小**——需求足够宽泛时，先切一个端到端能跑通的最小价值切片，其余部分进《需求池》排队（见第三节"按需创建"）。
3. **问题看必要性，不看数量**——该问的问，不该问的不问，不设数量上限；每个问题用"选择题+推荐答案"格式，答不上来就用推荐项转成❓假设，继续往下走。
4. **翻译层**——需要用户拍板的节点只讲体验/成本/时间/风险这类业务后果，禁止直接甩技术选型细节；附推荐+理由。
5. **轻量启动，按需扩展**——默认走最短路径：需求定稿 → 设计定稓 → 开发。探索机制、项目级共享文件（环境约束/需求池/决策日志）只在真正触发条件出现时才启用/创建，不预先搭建。触发条件见第三节。
6. **检查点确认，门禁不锁死**——阶段推进要用户确认；发现上游有误随时可回溯，走版本升级，不是打回重来。
7. **需求资产与认知资产分离**——探索中学到的东西默认写进探索日志，不改需求正文；只有证伪需求本身的假设，才把需求升版本。
8. **文件即记忆**——一切定稿必须落盘，不依赖任何工具的对话上下文。

## 二、反Plan Mode：三个具体机制

### ① 草案优先
拿到需求后第一动作永远是产出完整草案，不确定的地方用行内标记：
```
积分有效期：默认永久有效 ❓假设——如需过期规则请直接改这一行
```

### ② 问题处理规则（不设数量上限）
- **何时问**：同时满足"会实质改变需求方向或边界"+"只有用户能决定、AI无法用合理假设代替"，才问。技术实现细节、可类比行业惯例的点一律不问，直接假设。
- **怎么问**：选择题形式，附AI推荐项和理由，不用开放式提问。
- **答不上来怎么办**：用户说"不知道/你定/先这样"，AI直接采用推荐项，标❓假设，继续产出草案，不再追问同一个点。
- **防止滑回Plan Mode的唯一硬规则**：连续两轮只提问、没有产出任何草案或文档内容，视为违规，下一轮必须无条件先给出草案。
- 数量不设上限：可能0个问题，也可能一次问5个都合理，关键是"必要性"而不是"上限"。

### ③ 大切小（切片协议）
用户提出一个宽泛功能时，AI第一动作是识别出一个**端到端可跑通的最小价值切片**，只针对这个切片走完整流程，其余部分整理进"需求池"（首次真正触发才建 `docs/需求池.md`）。

## 三、文件骨架与"按需创建"触发条件

**默认最小路径**（大多数功能都走这条，只有2-3个文件）：
```
docs/
  agent-workflow-protocol.md
  PROGRESS.md
  <功能名>/
    01-requirements-v0.1.md   意图还原 + 需求正文 + 验收标准，合一文件
    03-design-v0.1.md         功能设计定稿
```

**按需追加**（满足触发条件才创建，不要提前建空文件）：

| 文件 | 触发条件 |
|---|---|
| `<功能名>/02-exploration-log.md` | Skill B判断"存在真正的技术不确定性"，需要走分支验证 |
| `docs/00-环境约束.md` | 某个设计决策被服务器/网络/端限制卡住，且这个限制大概率会影响以后其他功能 |
| `docs/需求池.md` | 第一次真正触发"大切小"，需要给切下来的部分排队 |
| `docs/decision-log.md` | 某次清算发现的认知被判断为"以后做别的功能也用得上" |

## 四、阶段自检固定格式（唯一定义，各Skill文件直接引用本节）

```
📍 阶段自检 | 当前阶段：<阶段名>
✅ <已完成项>
⬜ <未完成项>
状态：<全部完成 / 还有N项未完成>
👉 说"下一步"进入<下一阶段>；或直接补充/修正，我继续处理这一项。
```
用户说"跳过/先这样/进下一步" → 不追问、不重复提醒，⬜项写入下一阶段"遗留项"，正常推进。

## 五、清算模板（唯一定义，仅Skill B判断需要探索时使用）

```markdown
### 分支：explore/xxx （日期）

```

## 七、回溯协议

```
任何阶段发现上游文档有误 →
1. 说明：错在哪、怎么发现的、影响范围
2. 升版本号（如 v0.1→v0.2），新文件头部写清"相较上一版本的变更"，v0.1永久保留不覆盖
3. 标注受影响的下游文档
4. 用户确认后同步修正
```
"回滚"回到的是**当前有效的需求版本**，不是固定回到最初的v0.1。门禁只管节奏，不担保正确性——每份定稿只是"当前最佳认知"，版本号留出修正空间。

| 工具 | 定位 | 使用时机 |
