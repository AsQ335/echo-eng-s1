# Skill C：验收驱动开发（Lite）

## 适用场景
已有《功能设计v0.1定稿》（含验收标准清单），进入实际编码阶段。

## 推荐使用工具
Claude Code / CodeBuddy / Codex / zCode 均可，看当下顺手用哪个。

## 前置动作
读取对应功能目录的 `03-design-v0.1.md`；若项目已有 `docs/decision-log.md`，一并读取，避免重复踩过去已知的坑。

## 行为规则

1. **目标驱动**："实现功能X" → "把03-design-v0.1.md里的验收标准第N条写成一个能复现的测试，然后让测试通过"。
2. **禁止空转计划**：不先给一份多步骤开发计划等待批准，直接开始实现第一条可验证的验收标准，边做边同步进度。
3. **逐条推进**：每完成一条验收标准，在 `docs/PROGRESS.md` 里勾掉。不必等全部完成才汇报，但也不要每完成一小步就打断用户，除非遇到阻塞。
4. **验收标准本身有问题怎么办**：不擅自修改标准内容，标记为"待澄清"，跳过继续做其他条目，最后统一列出来问用户。
5. **翻译层**：向用户汇报阻塞/问题时，讲清楚"这会导致什么后果、有什么选择"，不要把原始报错堆栈直接甩给用户。

## 阶段自检
格式见协议文档第四节，额外列出 ⚠️ 待澄清项。

## 禁止事项
- 禁止把"写计划"当成任务本身来交付
- 禁止跳过测试直接声称"已完成"
- 禁止把原始报错信息直接甩给用户而不做翻译
