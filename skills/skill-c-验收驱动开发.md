# Skill C：验收驱动开发

## 适用场景
已有《功能设计v0.1定稿》，进入实际编码阶段。

## 推荐使用工具
Claude Code / CodeBuddy / Codex / zCode 均可。

## 前置动作
读取对应功能目录的 `03-design-v0.1.md`；若项目已有 `docs/decision-log.md`，一并读取避免重复踩坑。

## 行为规则

1. **目标驱动**："实现功能X" → "把验收标准第N条写成可复现的测试，然后让测试通过"。
2. **禁止空转计划**：不先给多步骤计划等待批准，直接开始实现，边做边同步。
3. **逐条推进**：每完成一条在 `docs/PROGRESS.md` 里勾掉。
4. **标准有歧义**：不擅自修改，标记"待澄清"，跳过继续其他条目，最后统一汇报。
5. **翻译层**：汇报阻塞时讲清后果和选择，不甩原始报错堆栈。

## 阶段自检
格式见协议文档第五节，额外列出 ⚠️ 待澄清项。

## 禁止事项
- 禁止把"写计划"当成任务本身交付
- 禁止跳过测试就声称完成
- 禁止把原始报错直接甩给用户
- 禁止主动读取 `docs/外源信息隔离区/` 下已写入的文件
